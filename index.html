Antes de arrancar

Tipos de Datos Abstractos (TDA)

Un TDA se define por su comportamiento — las operaciones que permite — y no por cómo está armado por dentro.

Pensalo como el volante de un auto: sabés que girándolo doblás, sin necesitar saber cómo está conectado mecánicamente. O el control remoto de un televisor: apretás subir volumen y no te importa si por dentro manda una señal infrarroja o bluetooth. Esa parte queda escondida.

Tres beneficios concretos salen de pensarlo así: modularidad, reutilización y mantenimiento — el código que usa el TDA no depende de sus detalles internos.

Tres características

Abstraccióndefine qué hace, no cómo lo hace
Encapsulaciónel código externo no ve los detalles internos
Independenciapodés cambiar la implementación sin romper nada afuera

En Python, la lista, la pila, la cola y el diccionario son TDA. Pila y cola quedan para más adelante — acá las nombramos solo como ejemplo.

Tuplas

Cuando necesitás guardar datos que no tienen que cambiar por accidente durante la ejecución: coordenadas de un punto, la fecha de nacimiento de alguien.

Es una secuencia ordenada e inmutable. Se accede por índice igual que en una lista, admite slicing (que siempre devuelve una tupla nueva, la original queda intacta), y se puede desempaquetar en variables distintas de una sola vez.

Gotcha clásico: una tupla de un solo elemento necesita la coma — (1,), no (1). Sin la coma, Python lo lee como un número común entre paréntesis.

Aunque es inmutable, tiene count e index para consultar, soporta + para concatenar y * para repetir. Y algo que se usa todo el tiempo: una función puede devolver varios valores separados por coma — Python los empaqueta en una tupla sola.

notas.py
notas = (7, 8, 6)
promedio = sum(notas) / len(notas)
print(f"Promedio: {promedio}")
# Promedio: 7.0

Video 03

Sets

Si alguna vez tuviste una lista con nombres repetidos y escribiste código extra solo para sacar los duplicados, un set te ahorra ese trabajo. Es una colección mutable de valores únicos: si agregás algo que ya está, no pasa nada.

No mantiene orden ni índice — no accedés por posición.

Gotcha: {} vacío crea un diccionario, no un set. Para un set vacío usá set().

Métodos: add, remove (falla si no existe), discard (no se queja), clear. Y las operaciones de conjuntos: | unión, & intersección, - diferencia, ^ diferencia simétrica.

sets_asistencia.py
asistencia = ["Ana", "Luis", "Ana", "Coco", "Luis", "Ana"]
unicos = set(asistencia)
conteo = {nombre: asistencia.count(nombre) for nombre in unicos}
print(conteo)
# {'Coco': 1, 'Luis': 2, 'Ana': 3}

Acá el set no reemplaza a la lista, la complementa: la lista guarda el historial completo, el set da la versión sin repetidos. Este patrón — lista para el historial, set para lo único — lo vas a ver todo el tiempo.

Video 04

Diccionarios

La estructura más usada de toda la unidad. En vez de acceder por posición, accedés por una clave que vos elegís: el nombre de un producto, un usuario, un id.

Es una colección de pares clave-valor, mutable, con claves únicas. Tres formas de acceder: corchetes (rompe con KeyError si la clave no existe), .get() (devuelve None si no existe), o .get(clave, default) con un valor por defecto.

.items(), .keys() y .values() no devuelven listas — devuelven objetos iterables propios de Python. Envolvelos con list() si necesitás indexarlos.

Gotcha: usar una lista como clave tira TypeError — las claves tienen que ser inmutables. Por eso una tupla sí puede ser clave, y una lista no.

precios.py
precios = {"pan": 500, "leche": 800, "arroz": 650}
precios["huevo"] = 900          # agregar
precios["pan"] = 550            # actualizar
productos = list(precios.keys())

Video 05

Diccionarios anidados

Un diccionario adentro de otro. Es la forma más natural de representar una entidad con varios campos — un contacto con teléfono y email, un alumno con nombre, nota y comisión — sin quilombo de variables sueltas.

Accedés encadenando corchetes: agenda["Ana"]["telefono"]. Para recorrerlo necesitás dos for: uno externo por cada contacto, uno interno con .items() por cada campo.

setdefault te asegura que exista una clave antes de usarla — si no está, la crea con un valor por defecto, así te ahorrás el KeyError.

agenda.py
agenda = {}
nombre = input("Nombre: ")
telefono = input("Telefono: ")
email = input("Email: ")
agenda[nombre] = {"telefono": telefono, "email": email}
print(agenda[nombre]["telefono"])

Video 06

Comprensiones, Counter y tupla como clave

Son atajos, no conceptos nuevos. Una comprensión arma una lista, set o diccionario en una sola línea a partir de un bucle — exactamente lo mismo que un for de varias líneas, comprimido.

Counter (de collections) cuenta automáticamente cuántas veces aparece cada elemento, sin que programes el conteo a mano. .most_common(n) te da los n más frecuentes.

Tupla como clave: una clave de diccionario tiene que ser hasheable (inmutable). Una tupla cumple esa condición — sirve para representar un turno con día y hora juntos, sin necesitar dos diccionarios.

turnos.py
turnos = {}
turnos[("martes", "15hs")] = "odontologo"

capitales = {"Argentina": "Buenos Aires"}
paises = {c: p for p, c in capitales.items()}
# invierte clave y valor en una línea

Video 07 — cierre

Cuándo usar cada uno

Elegir la estructura correcta depende de tres preguntas: ¿el orden te importa? ¿los datos van a cambiar? ¿puede haber valores repetidos? Y una razón de fondo más allá de la sintaxis: buscar por clave en un diccionario es prácticamente instantáneo; recorrer una lista buscando un valor se vuelve más lento cuantos más elementos tenga.

Herramienta — ¿qué estructura uso?

¿Necesitás buscar rápido por nombre o clave?

¿Los datos no deben cambiar una vez creados?

¿Necesitás valores únicos u operaciones de conjuntos (unión, intersección)?

{ : }

Usá un diccionario. Búsqueda por clave casi instantánea.

( )

Usá una tupla. Los datos quedan protegidos de cambios accidentales.

{ }

Usá un set. Sin duplicados, con operaciones de conjuntos.

[ ]

Usá una lista. Orden y mutabilidad sin restricciones extra.

Ejercicio integrador — Agenda de cumpleaños

Combina las tres estructuras que más usaste en la unidad: tupla, set y diccionario.

cumpleanos.py
cumples = [("Ana", "03-05"), ("Luis", "12-11"), ("Coco", "03-05")]

fechas_unicas = {fecha for _, fecha in cumples}
agenda = {nombre: fecha for nombre, fecha in cumples}

print(agenda["Luis"])
# 12-11

Tupla para juntar datos que van pegados (nombre + fecha), set para sacar lo único (fechas sin repetir), diccionario para buscar directo por nombre. Las tres estructuras que más vas a usar de acá en adelante.
